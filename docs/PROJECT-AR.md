# خزنة أستر — دليل المشروع (بالعربية)

> تطبيق سطح مكتب محلي بالكامل لنظام ويندوز، يحفظ كلمات المرور والأسرار على جهازك دون أي حساب
> أو سحابة أو رفع، مع واجهة عربية وإنجليزية ودعم حقيقي للكتابة من اليمين إلى اليسار، ونسخ
> احتياطية مشفّرة قابلة للاستعادة.

- **المستودع (خاص حاليًا):** https://github.com/waleedxe/aster-vault
- **الإصدارات:** `v0.1.0` و`v0.1.1` (مثبّتات ويندوز مبنية عبر CI؛ مسودات حتى تُنشر على صفحة Releases)
- **الاسم مؤقت:** «خزنة أستر» / Aster Vault — يجب التحقق من العلامة التجارية والنطاقات قبل النشر.

---

## 1) ما هو المشروع؟

مدير كلمات مرور سطح مكتب **يعمل محليًا بالكامل**:

- **لا حساب، ولا سحابة، ولا رفع، ولا تتبّع.** لا يخرج أي سر من جهازك.
- **التشفير كامل:** الحزمة كلها (العناوين، الروابط، أسماء المستخدمين، الوسوم، الملاحظات، وحتى
  رموز TOTP) مشفّرة — وليس كلمات المرور فقط.
- **العربية أولًا:** واجهة عربية/إنجليزية، تخطيط RTL/LTR، وتبديل لغة محفوظ.
- **النسخ الاحتياطي قابل للاستعادة دائمًا:** نسخة مشفّرة محمولة تعمل على حساب ويندوز نظيف
  بكلمة المرور الرئيسية أو مفتاح الاستعادة فقط — بلا ارتباط بالجهاز.
- **أداة استعادة مستقلة:** إذا تعطّلت الواجهة، يبقى بإمكانك استعادة نسخك عبر أداة سطر أوامر.

### الميزات (Release 1)

| الفئة | الميزات |
| --- | --- |
| العناصر | تسجيلات دخول · ملاحظات آمنة · بطاقات دفع · هويات · رموز TOTP |
| التنظيم | مجلدات/مجموعات · بحث محلي · مفضّلة · سجل تعديلات محدود لكل عنصر |
| التوليد | مولّد كلمات مرور (طول/أنواع أحرف/استبعاد المتشابهة) · عبارات مرور |
| الأمان المحلي | تحذير قوة كلمة المرور · كشف إعادة الاستخدام · إخفاء الحقول |
| الحماية | قفل تلقائي عند الخمول · مسح الحافظة بعد مؤقّت · تبديل كلمة المرور الرئيسية |
| النسخ الاحتياطي | إنشاء نسخة مشفّرة · التحقق منها · استعادة إلى خزنة جديدة · الاحتفاظ بعدد من الإصدارات |

> مزامنة سحابية. هذه في «الإصدار 2» و«الإصدار 3» وتُعدّ مشاريع أمنية منفصلة.

## 3) معمارية التطبيق (Architecture)

الفكرة الأساسية: **كل التشفير في صندوق واحد (`vault-core`)**، والواجهة وطبقة Tauri تبقى رقيقة.

```
الواجهة (React + TypeScript)
        │  استدعاء أمر Tauri (invoke)
        ▼
src-tauri/                 ← طبقة رقيقة: أوامر فقط
        ▼
crates/vault-core::session ← طبقة الخدمة (الجلسة، DTOs) — قابلة للاختبار بلا واجهة
        ▼
crates/vault-core          ← التشفير + الحاوية + المخزن + النسخ الاحتياطي
        │
        ▼
مكتبات مراجَعة (argon2 · aes-gcm · rand · zeroize)
```

### مجلدات المشروع

```text
src/                          واجهة React
  app/ (App, AppShell, معرض المكوّنات)
  components/common/ · components/ui/   المكوّنات المشتركة + نظام التصميم
  features/ (onboarding, unlock, vault, generator, import, backup, settings)
  stores/ hooks/ lib/ i18n/ test/
crates/vault-core/            التشفير والحاوية والمخزن والنسخ (بلا واجهة)
  src/crypto/ container/ model/ store/ backup/ generator.rs strength.rs session.rs
crates/vault-recovery-cli/    أداة استعادة مستقلة (سطر أوامر)
src-tauri/                    تطبيق Tauri (أوامر Rust فقط)
assets/brand/                 الشعار + مصدر الأيقونة
scripts/make-icon.py          يبني مصدر الأيقونة من الشعار (Python قياسي فقط)
docs/specs/                   نموذج التهديد · صيغة الخزنة · المعمارية · المخطط · الخطة
docs/PROJECT-AR.md            هذا الدليل
.github/workflows/            CI + الإصدار
```

### قاعدة التشفير (Adapter)

- **لا تشفير خارج `vault-core`.** لا تستخدم `aes-gcm` أو `argon2` في `src-tauri` أو `src`.
- أي محرّك/مكتبة تُستخدم خلف واجهة داخلية ثابتة — لا استدعاءات مباشرة منتشرة.
- أداة الاستعادة تعتمد على `vault-core` فقط، لذا لا يمكن أن تعلق نسخك بسبب عطل في الواجهة.

### نموذج الأمان (باختصار)

- مفتاح بيانات عشوائي **256-بت** من مولّد النظام، يُشفّر كل شيء.
- مفتاح رئيسي مشتق من كلمة مرورك عبر **Argon2id** (مع معاملات موصى بها ومحفوظة في الخزنة — 64 ميبي/3/1، دون قياس أداء عند الإعداد).
- **مسار استعادة مستقل** بمفتاح عشوائي عالي العشوائية.
- ترويسة **منسوخة الإصدار** مع بيانات مصادَقة (AAD)؛ أي تعديل أو فك تشفير خاطئ **يفشل بأمان**.
- التفاصيل الكاملة في `docs/specs/01-threat-model.md` و`docs/specs/02-vault-format.md`.

## 4) كيف نُنتج ملف `.exe` (وماذا فعلنا بالضبط)

هناك ثلاثة مسارات:

### المسار أ — البناء محليًا على ويندوز (للتجريب السريع)
المتطلبات (مرة واحدة):
1. **Rust** (MSVC): من https://win.rustup.rs
2. **Visual Studio Build Tools** مع حزمة **Desktop development with C++**
3. **Node.js 20+**

ثم في PowerShell داخل المشروع:
```powershell
cd C:\Users\walee\Desktop\PASS_MAN
npm install
npm run tauri build
```
النواتج:
- **المثبِّت (Next → Next → Install):**
  `target\release\bundle\nsis\Aster Vault_0.1.1_x64-setup.exe`
- **النسخة المحمولة (بلا تثبيت):**
  `target\release\aster-vault.exe`

> ملاحظة: لأن المشروع **Cargo workspace**، مجلد الإخراج هو `target` في **جذر المشروع**، وليس
> داخل `src-tauri\target`.

لتشغيل نسخة تطوير سريعة: `npm run tauri dev`.

### المسار ب — البناء عبر GitHub (هذا ما استخدمناه — الأسهل)
1. ارفع الكود إلى فرع `main` (تم).
2. أنشئ وسم إصدار وارفعه (مثال: الإصدار الحالي `v0.1.1`):
   ```bash
   git tag v0.1.1
   git push origin v0.1.1
   ```
3. يعمل سير عمل **Release** على جهاز ويندوز في GitHub ويبني:
   - المثبِّت `Aster.Vault_0.1.1_x64-setup.exe`
   - النسخة المحمولة `aster-vault.exe`
   ويرفعها إلى صفحة **Releases** (كمسودة حتى تنشرها).

هذا ما أنتج الإصدارين `v0.1.0` و`v0.1.1` الموجودين على سطح المكتب.

### المسار ج — CI للتحقق فقط
عند أي `push` إلى `main` يعمل سير عمل **CI** (فحص الواجهة + lint/typecheck/tests + اختبارات
Rust + clippy).

> **ملاحظة مهمة:** البناء يجب أن يكون بـ **MSVC على ويندوز**. لا يمكن بناء تطبيق Tauri هذا
> محليًا على لينكس في بيئتنا (لا تتوفّر حزمة WebKitGTK)، لذلك يُبنى على جهاز ويندوز في CI.

## 5) إذا كانت لدي ميزة جديدة… ما العملية؟

اتبع نفس النمط (لا تكسر البنية). الخطوات:

1. **المنطق في `crates/vault-core`**
   - أضف الوحدة/الدالة في الوحدة المناسبة (`model/`, `store/`, `crypto/`, `backup/`, …).
   - صدّرها من `lib.rs`.
   - أضف اختبارات تكامل في `crates/vault-core/tests/`.

2. **طبقة الخدمة في `crates/vault-core/src/session.rs`**
   - أضف دالة على `VaultSession` تعمل على الخزنة المفتوحة، وأعِد DTO مناسبًا للواجهة.

3. **أمر Tauri في `src-tauri/src/commands/mod.rs`**
   - أضف دالة `#[tauri::command]` تستدعي `session`.
   - سجّلها في `src-tauri/src/lib.rs` داخل `generate_handler!`.

4. **الواجهة في `src/features/<الاسم>/`**
   - مكوّن React يستدعي الجسر المكتوب في `src/lib/tauri.ts` (لا تستدعِ `invoke` مباشرة من
     المكوّنات).
   - أضف النصوص في `src/i18n/en.json` و`src/i18n/ar.json` (يجب أن تتطابق المفاتيح تمامًا —
     هناك اختبار يتحقق من ذلك).

5. **التحقق (مهم — لا تُجمّع مراحل مكسورة)**
   ```bash
   cargo fmt --all
   cargo clippy -p vault-core -p vault-recovery-cli --all-targets -- -D warnings
   cargo test  -p vault-core -p vault-recovery-cli

   npm run format:check && npm run lint && npm run typecheck && npm run test && npm run build
   ```

6. **النشر**
   - `git commit` ثم `git push` (يعمل CI تلقائيًا).
   - إصدار جديد: `git tag v0.1.1 && git push origin v0.1.1` → سير عمل Release ينتج المثبِّت.

### قواعد ثابتة
- **لا تشفير مكتوب يدويًا، ولا نونسات مُعاد استخدامها، ولا مفاتيح مخزّنة.**
- لا تضع أسرارًا في السجلات أو الاختبارات أو مخرجات الأخطاء.
- الخزنة السابقة لا تُستبدل أبدًا قبل التحقق من النسخة الجديدة وتأكيد المستخدم.
- حافظ على العربية أولًا: اختبر RTL عند أي تغيير يمسّ الواجهة.

## 7) ملاحظات مهمة وخارطة الطريق

- **الخصوصية:** لا رفع، لا سحابة، لا تتبّع، ولا أي محتوى أسرار في القياسات. انظر `PRIVACY.md`.
- **الشعار والأيقونة:** الشعار النهائي في `assets/brand/aster-mark.png`، وتُبنى أيقونة التطبيق عبر
  `npm run icon:build`.
- **التوقيع الرقمي:** التطبيق غير موقّع حاليًا، لذا قد يظهر تحذير SmartScreen مرة واحدة:
  More info → Run anyway. يمكن إضافة التوقيع لاحقًا.
- **WebView2:** مطلوب، وهو مثبّت افتراضيًا في ويندوز 10/11.
- **المراجعة الأمنية:** **لم تخضع النسخة لمراجعة أمنية مستقلة بعد.** لا تخزّن كلمات مرورك
  الأكثر حساسية حتى تكتمل المراجعة.
- **رخصة المشروع:** MIT (سيُفتح لاحقًا كمصدر مفتوح). كل المكتبات برخص متسامحة.

### خارطة الطريق

- **الإصدار 2** — إضافة متصفح Chrome/Edge بأذونات ضيقة، مطابقة أصل مقاومة للتصيّد، وملء تلقائي
  فقط بعد تواصل موثّق مع التطبيق. مشروع أمني منفصل (انظر `docs/specs/06-browser-extension-r2.md`).
- **الإصدار 3** — مزامنة مشفّرة اختيارية (مشروع أمني منفصل). لا تُوصف بأنها «صفرية المعرفة»
  قبل تقييم مستقل.

### ما لا يستطيع المشروع حمايتك منه

- برمجية خبيثة على جلسة مفتوحة قد تقرأ الأسرار.
- نظام تشغيل أو ملف تنفيذي مخترق يُبطل أي تشفير محلي.
- لا يمكن جعل الحافظة ذرّية، ولا ضمان الحذف الآمن على أقراص SSD.
- فقدان كلمة المرور **ومفتاح الاستعادة** معًا = استحالة الاستعادة (بالتصميم).
